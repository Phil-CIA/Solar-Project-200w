Decision policy: move fast, log every non-trivial choice, and defer only with a target date.

## How We Use This Log

1. Record each meaningful technical or process choice the same day it is made.
2. If a decision is deferred, assign an owner and target decision date.
3. Link each decision to impacted requirements or architecture sections once those docs are created.
4. Review unresolved items at least once per week or at the start of any design session.

## Status Legend

- Decided: accepted baseline for current phase.
- Deferred: intentionally delayed until prerequisite information exists.
- Open: needs discussion now; blocks near-term progress.

## Change Log

- 2026-08-26: Added DEC-019 and DEC-020, and added the mandatory Part Substitution Gate (Section 7.2) to `hardware/mppt/kicad-implementation-checklist.md`. Audited the remaining Rev 0 MCU net assignments while verifying `STM32G473CEU6` before ordering. UART is correct (U3 pin names are from the bridge perspective, so `PA9`/TX to bridge RXD and `PA10`/RX to bridge TXD is proper). I2C is swapped at the MCU and is logged as DEC-019. `PB11` (pad 24) is tied to `PWR_NEG` and must never be configured as an output. `PB8`/BOOT0 (pad 46) floats, which is acceptable at default G4 option bytes (`nBOOT_SEL=1`).
- 2026-08-26: Added DEC-018 and superseded DEC-017. Confirmed true root cause of the U1 short: the Rev 0 board was routed against the `STM32G431CBU6` symbol while `STM32F411CEU6` parts were fitted. The DEC-014 migration changed only the `Value`/`MP` text fields, not the symbol `lib_id`, so the pin map was never updated. Verified against KiCad's official `STM32F411CEUx` library: pads 23 and 35 carry `CTRL_3V3` but are `VSS` on F411, and pad 24 carries `PWR_NEG` but is `VDD` on F411, creating two hard short paths through the die. Additional consequences of the same mismatch: `VSSA` (pad 8) and `VDDA` (pad 9) unconnected, `VCAP1` (pad 22) has no capacitor, `BOOT0` (pad 44) driven by `I2C DATA`, `BOOT1` (pad 20) tied high, and `VDD` (pad 36) wired to `SWDIO`. Existing Rev 0 boards are correctly routed for `STM32G431CBU6`; no rework can make `STM32F411CEU6` work on this layout.
- 2026-08-26: Added DEC-017 and closed Q-005. Cross-testing confirmed the U1 `CTRL_3V3`-to-`PWR_NEG` short is a Rev 0 footprint/design-level defect, not a single bad chip or single bad board: the original chip on the original board, a new spare chip on the original board, and the original chip on a second unpopulated board all read the same short. Stopped further chip-swap troubleshooting. Next step for existing Rev 0 boards is targeted salvage rework (cut the suspect copper bridge at the pad 1/48 or pad 24/25 corner and verify with U1 off, or pre-dam the exposed-pad clearance with Kapton/solder-mask pen before reflow); DEC-016 remains the permanent Rev 1 footprint fix.
- 2026-08-26: Added DEC-016. Rev 0 bench debugging on U1 suggests the pad 24/49 corner (`PWR_NEG` break-out next to the exposed pad, same net) may act as a solder-migration channel under the package toward the pad 1/48 (`CTRL_3V3`) corner during reflow. Rev 1 will add exposed-pad relief vias and wider solder-mask dams at all four corners for fine-pitch QFN footprints, starting with the STM32 placement.
- 2026-08-26: Updated Q-005 with a planned isolation test: mount the current suspect U1 (not the guarded spare) on a second, otherwise unpopulated Rev 0 board of the same layout/fab lot, after confirming that board reads open at `CTRL_3V3`-to-`PWR_NEG` with nothing installed. A short reappearing there would confirm the chip is bad across two boards; a clean reading would point to a footprint-level defect specific to the original board.
- 2026-08-26: Corrected Q-005. The prior "no shorted pins" check was performed on the isolated chip, not bare board pads. Since both the isolated chip and the bare board test clean individually, but a clean reseated joint still reads 0.7 ohm, the leading theories shift to a footprint-level cause (solder-mask clearance, thermal-via wicking, or U1 bridging two otherwise-separate copper segments) rather than a simple bad IC. Decision branch: try a replacement U1; if the new chip also reads 0.7 ohm once mounted, treat the fault as board-located at that footprint and stop further chip swaps.
- 2026-08-26: Updated Q-005 with confirmed diagnostic result. Bare-board pin-to-pad-49 continuity checks with U1 removed show no shorted pins, and a full rework cycle (wick, alcohol clean, fresh low-temp paste, clean reseat) still reads 0.7 ohm every time U1 is reinstalled. PCB and solder-joint causes are ruled out; the short is internal to this specific U1 unit. Action: replace U1 rather than continue rework; use ESD precautions and minimize reflow cycles on the replacement part.
